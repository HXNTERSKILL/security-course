## 3. Расследование инцидента

### Хронология действий bob

| Время | Действие | Результат | Источник (команда поиска) |
|-------|----------|-----------|---------------------------|
| 14:40:11 | cat /etc/shadow | Отказ (Permission denied) | ausearch -k access-denied |
| 14:40:15 | ls /root | Отказ (Permission denied) | ausearch -k access-denied |
| 14:40:18 | cat /etc/passwd | Успех | ausearch -k auth-files |
| 14:40:22 | touch /tmp/totally-not-malware.sh | Успех | grep в ausearch |
| 14:40:28 | cat /etc/sudoers | Отказ (Permission denied) | ausearch -k access-denied |

### Как auditd помог расследованию

Auditd зафиксировал все действия bob, включая **неудачные попытки** доступа к защищённым файлам. Благодаря ключам (`-k`) мы смогли быстро найти все события, связанные с отказом доступа и доступом к файлам аутентификации. Поле `auid` позволило однозначно идентифицировать bob, даже если бы он использовал sudo.

### Чем auditd лучше journalctl для задач аудита безопасности

| Характеристика | auditd | journalctl |
|----------------|--------|------------|
| Уровень работы | Ядро ОС | Пользовательское пространство |
| Фиксация всех syscall | Да | Нет |
| Отслеживание неудачных попыток | Да (все) | Только если приложение их записало |
| Обход приложением | Невозможно | Возможно |
| AUID (неизменный ID) | Есть | Нет |
| Поиск по ключам | Да (-k) | Нет |
| Мониторинг конкретных файлов | Да (-w) | Нет |

## 5. Ответы на контрольные вопросы

**65. Чем отличается auditd от journald? Почему нельзя обойтись только journald?**

auditd работает на уровне ядра и фиксирует ВСЕ системные вызовы. Приложение не может "скрыть" свои действия от auditd. journald собирает логи от приложений — если приложение решит не писать лог, journald ничего не узнает.

**66. Что такое auid и почему оно важнее uid при расследовании?**

auid (Audit User ID) — это ID пользователя, который изначально вошёл в систему. При использовании sudo поле uid меняется на 0 (root), а auid остаётся исходным. Без auid все действия через sudo выглядели бы как действия root.

**67. Что означает флаг -k в auditd?**

`-k` задаёт ключ (метку) для события. Потом можно искать по этому ключу: `ausearch -k имя_ключа`. Нужен для группировки связанных событий.

**68. Чем -w отличается от -a always,exit?**

| Флаг | Назначение | Пример |
|------|------------|--------|
| `-w` | Следить за файлом/директорией | `-w /etc/passwd -p rwa` |
| `-a always,exit` | Следить за системными вызовами | `-a always,exit -S open -F success=0` |

**69. Что если злоумышленник удалил /var/log/audit/audit.log? Как защититься?**

Удаление логов помогает скрыть следы. Защита:
- Настроить удалённое логирование на другой сервер
- Использовать неизменяемые атрибуты: `chattr +a /var/log/audit/audit.log`
- Настроить оповещение при остановке auditd

**70. Что нужно чтобы правила сохранились после перезагрузки?**

Правила нужно поместить в файл `/etc/audit/rules.d/`. При загрузке система выполнит `augenrules --load`. В работе мы создали файл `security-course.rules`.

### Команды, использованные в работе

| Команда | Что делает |
|---------|------------|
| `journalctl -f` | Мониторинг логов в реальном времени |
| `journalctl _COMM=sudo` | Логи только sudo |
| `journalctl --since "30 minutes ago"` | Логи за 30 минут |
| `sudo auditctl -w /etc/passwd -p rwa -k auth-files` | Мониторинг файла |
| `sudo ausearch -k access-denied -i` | Поиск отказов доступа |
| `sudo aureport` | Сводный отчёт |
| `sudo augenrules --load` | Загрузка правил |
