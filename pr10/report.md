ПР №10. Обнаружение вторжений: fail2ban и Suricata
1. Введение: зачем нужны IDS/IPS
Фаервол (Firewall) — система фильтрации входящего/исходящего трафика. Он работает по статическим правилам (разрешить/запретить порты, IP, протоколы). Фаервол не анализирует, что происходит внутри разрешённого соединения.

Система обнаружения вторжений (IDS — Intrusion Detection System) — анализирует трафик и логи, находит подозрительную активность и поднимает тревогу.

Система предотвращения вторжений (IPS — Intrusion Prevention System) — делает то же, что и IDS, но при этом активно вмешивается: блокирует IP, разрывает соединения, отсекает трафик.

Аналогия: IDS — это сигнализация в доме, которая просто издаёт звук. IPS — это сигнализация, которая захлопывает дверь перед носом вора.

2. Классификация систем обнаружения
По месту наблюдения:
Тип	Что видит	Примеры
HIDS (Host-based IDS)	Логи и события одного хоста	fail2ban, auditd, OSSEC
NIDS (Network-based IDS)	Весь сетевой трафик сегмента	Suricata, Snort, Zeek
HIDS видит, что происходит внутри ОС: кто залогинился, какие команды выполнял, какие файлы менял. NIDS видит атаки на сетевом уровне, но не видит, что происходит внутри хоста. Лучшая защита — использовать оба инструмента одновременно (эшелонированная защита).

По способу обнаружения:
Тип	Суть	Плюсы	Минусы
Сигнатурный анализ	Сравнение с базой шаблонов атак	Высокая точность, мало ложных срабатываний	Не обнаруживает новые, неизвестные атаки
Обнаружение аномалий	Поиск отклонений от нормального поведения	Может найти то, что никто не видел	Много ложных срабатываний
fail2ban и Suricata используют преимущественно сигнатурный подход.

3. Брутфорс и его разновидности
Брутфорс (brute force) — подбор пароля перебором.

Тип	Описание
Простой брутфорс	Перебор всех возможных комбинаций символов (очень долго)
Словарный	Перебор по списку популярных паролей (быстрее)
Credential stuffing	Использование слитых логин/пароль из других сервисов
Password spraying	Один и тот же пароль пробуется на множестве аккаунтов (чтобы не вызвать блокировку)
4. fail2ban: охранник, который читает логи
fail2ban — это HIDS-система, которая читает логи сервисов (SSH, nginx, Apache и др.) и при обнаружении неудачных попыток блокирует IP-адрес нарушителя.

Ключевые понятия:
Термин	Описание
Jail ("тюрьма")	Блокировка для конкретного сервиса. У каждой тюрьмы свои настройки: какой сервис мониторить, какой фильтр, сколько попыток считать критичными
Filter	Регулярное выражение, описывающее, как выглядит неудачная попытка
Action	Что делать, когда фильтр сработал нужное число раз (обычно — бан IP)
Решающие параметры:
Параметр	Описание
maxretry	Сколько неудачных попыток допускается до бана
findtime	За какой период времени считаются попытки (окно наблюдения, в секундах)
bantime	На сколько времени банить IP после превышения лимита (в секундах)
Структура конфигурации:
Файл	Назначение
/etc/fail2ban/jail.conf	Основной конфиг (не редактировать!)
/etc/fail2ban/jail.local	Свои настройки, переопределяют jail.conf
/etc/fail2ban/jail.d/*.conf	Альтернативный способ — отдельные файлы для каждой тюрьмы
/etc/fail2ban/filter.d/	Готовые фильтры для разных сервисов (sshd.conf, nginx-http-auth.conf)
/etc/fail2ban/action.d/	Готовые действия (что делать при бане)
Пример настройки тюрьмы для SSH:
ini
[sshd]
enabled = true
port = ssh
filter = sshd
backend = systemd
maxretry = 3
findtime = 600
bantime = 600
Прогрессивное увеличение времени бана:
ini
bantime.increment = true
bantime.factor = 2
При повторных нарушениях время бана увеличивается: первый бан — 30 минут, при повторном нарушении после разбана — уже час, потом два часа и так далее.

5. hydra — инструмент для брутфорса
hydra — утилита для перебора паролей к различным сетевым сервисам.

Основные параметры:
Параметр	Описание
-l логин	Конкретное имя пользователя
-L файл	Файл со списком имён пользователей
-p пароль	Конкретный пароль
-P файл	Файл со списком паролей (словарь)
-t N	Количество параллельных потоков
-V	Подробный вывод, показывает каждую попытку
-f	Остановиться после первой успешной находки
Пример команды:
bash
hydra -l bruteforce-target -P /tmp/passwords.txt -t 1 -V ssh://192.168.1.100
Словарь паролей (пример):
text
123456
password
admin
qwerty
letmein
monkey
dragon
football
iloveyou
6. Suricata: сетевой страж
Suricata — это NIDS/IPS система с открытым исходным кодом. Она анализирует сетевой трафик в реальном времени и может как сигнализировать, так и блокировать подозрительные соединения.

Структура правил Suricata:
text
действие протокол откуда_адрес откуда_порт направление куда_адрес куда_порт (опции)
Пример правила для обнаружения SSH-брутфорса:
text
alert tcp any any -> $HOME_NET 22 (msg:"Возможный SSH брутфорс"; flow:to_server; flags:S; threshold:type both, track by_src, count 5, seconds 60; sid:1000001; rev:1;)
Разбор правила:
Элемент	Описание
alert	Действие (сигнализировать)
tcp	Протокол
any any	Любой IP, любой порт (источник)
->	Направление трафика
$HOME_NET 22	Домашняя сеть, порт 22 (SSH)
msg	Сообщение, которое появится в логе
flow:to_server	Отслеживаем трафик к серверу
flags:S	Только SYN-пакеты (начало соединения)
threshold	Порог срабатывания
count 5, seconds 60	5 попыток за 60 секунд
sid	Уникальный ID правила
Где живут правила и логи:
Файл/папка	Назначение
/etc/suricata/suricata.yaml	Основной конфиг
/etc/suricata/rules/	Папка с файлами правил
/var/log/suricata/fast.log	Простой текстовый лог алертов
/var/log/suricata/eve.json	Подробный JSON-лог (машиночитаемый)
Форматы логов:
fast.log (текстовый, для быстрого просмотра):

text
05/21/2024-14:30:15.123456  [**] [1:1000001:1] Возможный SSH брутфорс [**] {TCP} 192.168.1.50:54321 -> 192.168.1.100:22
eve.json (JSON, для SIEM):

json
{
  "timestamp": "2024-05-21T14:30:15.123456+0000",
  "flow_id": 1234567890,
  "event_type": "alert",
  "src_ip": "192.168.1.50",
  "dest_ip": "192.168.1.100",
  "alert": {
    "action": "allowed",
    "signature_id": 1000001,
    "signature": "Возможный SSH брутфорс"
  }
}
Готовые наборы правил:
Emerging Threats (ET Open) — бесплатный набор правил

Обновление правил: sudo suricata-update

7. Сравнение fail2ban vs Suricata
Аспект	fail2ban	Suricata
Тип	HIDS (на уровне хоста)	NIDS (на уровне сети)
Источник данных	Логи сервисов (sshd, nginx)	Сетевой трафик
Метод обнаружения	Регулярные выражения в логах	Сигнатурный анализ пакетов
Блокировка	Да (через iptables)	По умолчанию нет (только алерт)
Видит ли	Только неудачные логины	SYN-пакеты на порт 22
Когда реагирует	После фиксированного числа неудач	При превышении порога SYN/сек
Почему их стоит использовать вместе:
fail2ban защищает от перебора на уровне приложения (видит неудачные логины)

Suricata видит атаку на сетевом уровне, когда fail2ban ещё не сработал

Вместе дают эшелонированную защиту: сетевой уровень (Suricata) + хост (fail2ban)

8. Механизм блокировки в fail2ban
fail2ban блокирует IP через iptables (или другие файрволы):

text
Chain f2b-sshd (1 references)
target     prot opt source         destination
REJECT     all  --  192.168.1.50   0.0.0.0/0
Это означает, что все пакеты с забаненного IP отклоняются на уровне ядра.

9. Связь с нормативной базой (Приказ ФСТЭК №17)
Группа мер	Конкретная мера	Как реализуется
АУД (Аудит безопасности)	АУД.4 — анализ защищённости	Логирование неудачных попыток входа
УПД (Управление доступом)	УПД.3 — управление доступом субъектов	fail2ban блокирует IP при превышении лимита
ЗИС (Защита от НСД)	ЗИС.17 — управление сетевыми соединениями	Suricata мониторит сетевой трафик
АНЗ (Антивирусная защита)	АНЗ.2 — обнаружение вредоносного ПО	Обнаружение аномалий в трафике
Контрольные вопросы
Вопрос	Ответ
Чем IDS отличается от IPS?	IDS — сигнализирует, IPS — сигнализирует и блокирует автоматически
Что такое HIDS и NIDS?	HIDS — на хосте (логи), NIDS — на сети (трафик)
Почему localhost не работает для fail2ban?	ignoreip по умолчанию содержит 127.0.0.1/8
Сигнатуры vs Аномалии?	Сигнатуры — ищут известные паттерны, аномалии — отклонения от нормы
Suricata alert vs block?	По умолчанию только сигнализирует, нужно настраивать для блокировки
Что означает threshold в правиле Suricata?	count 5, seconds 60 — 5 пакетов за 60 секунд с одного источника
Зачем bantime.increment?	Увеличивает время бана при повторных нарушениях
Что такое SBOM?	Список компонентов ПО с версиями и лицензиями (для compliance)
Чем AGPL отличается от GPL?	AGPL требует открывать код даже для SaaS, GPL — только при распространении
