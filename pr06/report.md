# ПР №6. Анализ сетевого трафика: tcpdump и Wireshark

## 1. Разбор строки tcpdump

Строка: `22:37:26.973302 IP 192.168.47.131.49684 > 140.82.121.4.443: Flags [S], seq 4182378370, win 64240, length 0`

| Поле | Значение | Что означает |
|------|----------|---------------|
| 22:37:26.973302 | Время | Точное время захвата пакета |
| IP | Протокол | Используется IPv4 |
| 192.168.47.131.49684 | Источник | IP и порт отправителя (моя ВМ) |
| 140.82.121.4.443 | Назначение | IP и порт получателя (GitHub, HTTPS) |
| Flags [S] | Флаг SYN | Начало TCP соединения (handshake) |
| length 0 | Длина | Нет данных в пакете |

## 2. Перехват HTTPS трафика

Был выполнен захват HTTPS трафика на порту 443.

**Что видно в трафике:** Только IP-адреса, порты и TCP-флаги. Содержимое зашифровано и нечитаемо.

## 3. Перехват DNS запросов

Был выполнен захват DNS трафика на порту 53.

**Что видно в DNS:** Доменные имена запрашиваемых сайтов (например, google.com, github.com)

**Это означает:** Даже при использовании HTTPS злоумышленник видит какие сайты посещает пользователь, но не видит что именно он там делает.

## 4. HTTP vs HTTPS - теоретическое сравнение

| Что наблюдаем | HTTP (порт 80) | HTTPS (порт 443) |
|---------------|----------------|------------------|
| IP-адреса | Видны | Видны |
| Порт назначения | Виден (80) | Виден (443) |
| Заголовки HTTP | Видны открыто | Зашифрованы |
| Тело запроса | Видно открытым текстом | Зашифровано |
| Логин/пароль | Передаются открыто | Не видны |
| Имя домена | Видно в Host | Видно только в SNI |

## 5. DNS и приватность

**Какие домены видны в DNS:** google.com, github.com, example.com

**Что это означает для приватности:** 
- HTTPS защищает содержимое, но не скрывает факт посещения сайта
- Провайдер и любой в сети видит какие сайты вы открываете
- Для полной приватности нужно использовать VPN или DNS over HTTPS (DoH)

## 6. Base64

Пример кодирования Base64:
echo -n 'login:password' | base64
bG9naW46cGFzc3dvcmQ=

echo 'bG9naW46cGFzc3dvcmQ=' | base64 -d
login:password

**Почему Base64 не является шифрованием:**
- Base64 - это просто кодирование, как перевод в другую азбуку
- Нет секретного ключа - любой может декодировать обратно
- Это не обеспечивает конфиденциальность, только совместимость с текстовыми протоколами

## 7. tshark vs tcpdump vs Wireshark

| Инструмент | Когда использовать |
|------------|---------------------|
| tcpdump | Быстрый захват на сервере, минималистичный, нет GUI |
| tshark | Автоматизация, скрипты, анализ без графического интерфейса |
| Wireshark | Глубокий визуальный анализ, удобен для обучения и расследований |

## 8. Каналы утечки через сеть

**Основные каналы утечки:**
- Незашифрованный HTTP трафик
- DNS запросы (даже при HTTPS)
- Метаданные TLS (размеры пакетов, время передачи)

**Меры защиты:**

| Мера | Назначение |
|------|-------------|
| HTTPS/TLS | Шифрование данных |
| DNS over HTTPS (DoH) | Скрытие DNS запросов |
| VPN | Полное шифрование всего трафика |
| Шифрование на уровне приложения | Дополнительный слой защиты |

## 9. Ответы на контрольные вопросы

**78. Что такое promiscuous mode?**
Режим сетевого интерфейса, при котором он принимает ВСЕ пакеты в сети, а не только адресованные ему. Нужен снифферу для перехвата чужого трафика.

**79. Capture filter vs Display filter?**
- Capture filter - фильтрует ПЕРЕД записью (синтаксис tcpdump)
- Display filter - фильтрует УЖЕ захваченные пакеты (синтаксис Wireshark)

**80. Follow TCP Stream в Wireshark?**
Собирает все пакеты одного TCP соединения и показывает полный диалог клиента и сервера в читаемом виде (красное - запрос, синее - ответ).

**81. Почему Base64 не защита?**
Это кодирование, не шифрование. Нет ключа, любой может декодировать. Для защиты нужно реальное шифрование (TLS, GPG).

**82. Какие данные утекают даже при HTTPS?**
- Домены через DNS и SNI
- IP адреса
- Размеры пакетов (можно угадать тип данных)
- Время передачи

**Исправление:** Использовать DoH, DoT или VPN.

**83. Свитч и сниффинг?**
Не совсем прав. На свитче сложнее, но возможен ARP-spoofing или порт-мимикри.
