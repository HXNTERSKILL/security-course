ПР №9. Лицензирование, SPDX и open-source compliance
1. Выбор лицензии
Выбранная лицензия: MIT
Тип: разрешительная (permissive)

Что разрешает: использовать, копировать, изменять, объединять, публиковать, распространять, сублицензировать, продавать код

Что требует: сохранять уведомление об авторских правах (Copyright notice) и текст лицензии во всех копиях или значительных частях кода

Может ли кто-то продавать ваш код: Да, но с обязательным указанием вашего авторства

Почему выбрана MIT: Это самая простая и популярная разрешительная лицензия. Она не требует раскрывать исходный код производных продуктов, что делает её удобной для учебных и коммерческих проектов.

4. SPDX-заголовки и спецификация REUSE
4.1 Что такое SPDX
SPDX (Software Package Data Exchange) — стандарт Linux Foundation для описания лицензий. Использует машиночитаемые идентификаторы вместо длинных текстов лицензий.

Основные SPDX-идентификаторы:

MIT — MIT License

Apache-2.0 — Apache License 2.0

GPL-3.0-only — GNU GPL v3.0

BSD-3-Clause — BSD 3-Clause

4.2 Добавленные SPDX-заголовки
В файлы отчёта были добавлены SPDX-заголовки вручную:

<!-- SPDX-FileCopyrightText: 2026 DANIIL -->
<!-- SPDX-License-Identifier: MIT -->
Что означает каждая строка:

SPDX-FileCopyrightText — указывает автора и год создания файла

SPDX-License-Identifier — указывает лицензию под которой распространяется файл

4.3 REUSE Specification
Спецификация REUSE требует, чтобы каждый файл в репозитории содержал информацию о лицензии. Три правила REUSE:

Каждый файл должен содержать SPDX-заголовок

Полные тексты всех используемых лицензий лежат в папке LICENSES/

Все copyright notices указаны в заголовках файлов

name: License Check

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  reuse:
    name: REUSE compliance check
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: REUSE compliance check
        uses: fsfe/reuse-action@v3
Он автоматически проверяет соответствие спецификации REUSE при каждом push и pull request в ветку main.

8. Анализ совместимости лицензий
Сценарий 1: MIT + GPL в коммерческом продукте
Вопрос	Ответ
Можно ли?	 Нет
Обоснование	GPL-код требует, чтобы весь производный продукт распространялся под GPL. Если продукт коммерческий и закрытый — использовать GPL нельзя.
Решение	Использовать альтернативную библиотеку под MIT/Apache-2.0 или открыть исходный код продукта.
Сценарий 2: Apache-2.0 + MIT
Вопрос	Ответ
Можно ли?	 Да
Обоснование	Обе лицензии разрешительные. MIT совместима с Apache-2.0. Нужно сохранить оба уведомления об авторстве.
Решение	Никаких дополнительных действий не требуется, просто сохранить оба COPYRIGHT.
Сценарий 3: MIT без указания авторства
Вопрос	Ответ
Можно ли?	 Нарушение
Обоснование	MIT требует сохранять уведомление об авторских правах во всех копиях или значительных частях кода.
Решение	Всегда указывать оригинальное авторство в файлах.
Сценарий 4: AGPL в SaaS
Вопрос	Ответ
Можно ли?	 Нет
Обоснование	AGPL требует открыть исходный код даже для SaaS-сервисов (в отличие от обычной GPL, которая требует открытия только при распространении).
Решение	Использовать альтернативу или открыть исходники сервиса.
Сценарий 5: Репозиторий без LICENSE
Вопрос	Ответ
Можно ли?	 Нельзя
Обоснование	Без лицензии действует авторское право по умолчанию — никто не может использовать, копировать или изменять код без разрешения автора.
Решение	Добавить LICENSE в репозиторий.

10. Что такое SBOM
SBOM (Software Bill of Materials) — список всех компонентов программного продукта с указанием версий и лицензий.

Зачем нужен SBOM:

Compliance: знаешь лицензии всех зависимостей

Безопасность: можно быстро проверить затронут ли продукт новой уязвимостью

Регуляторные требования: в США SBOM обязателен для ПО, поставляемого федеральному правительству

Форматы SBOM: SPDX, CycloneDX, SWID.

Контрольные вопросы
Вопрос	Ответ
Чем MIT отличается от GPL?	MIT — разрешительная, позволяет использовать код в закрытых продуктах. GPL — копилефтная, требует открывать исходный код производных продуктов (так называемый "вирусный эффект").
Что такое SPDX?	SPDX (Software Package Data Exchange) — стандарт Linux Foundation для описания лицензий. Использует машиночитаемые идентификаторы (например, MIT, GPL-3.0-only).
Можно ли использовать код без LICENSE?	Нет. Без лицензии все права защищены по умолчанию. Код можно смотреть, но нельзя использовать, копировать или изменять без разрешения автора.
Зачем нужен SBOM?	SBOM нужен для compliance (проверка лицензий) и безопасности (отслеживание уязвимостей в зависимостях).
В чём отличие AGPL от GPL?	AGPL требует открывать исходный код даже для SaaS-сервисов (в отличие от GPL, которая требует только при распространении). Закрывает "облачную лазейку".
